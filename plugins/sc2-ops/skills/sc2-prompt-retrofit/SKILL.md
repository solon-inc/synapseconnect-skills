# sc2-prompt-retrofit — システムプロンプトへの SynapseConnect 組み込み・最適化

渡されたシステムプロンプトを、SynapseConnect の現行推奨（2層構成 = 基本ルール + 手順スキル参照）に合わせて修正する。
正本は `references/base-rules.md`（組み込む基本ルール）と `references/audit-checklist.md`（現行方針のチェックリスト）。

## なぜこの形か（先に読む）

- プロンプトは「全体ルールと発動タイミング」だけを持ち、手順（どう探すか・どの棚にどんな粒度で書くか）は
  スキル「記憶の検索」「記憶の記録」が持つ。プロンプトに手順を書き込むと、手順の改訂のたびに
  全プロンプトの書き直しが要るため。
- 元のプロンプトは顧客の資産。SynapseConnect に関係しない記述（役割・人格・業務ルール・文体）を
  変えると、修正の検収ができなくなる。触るのは SynapseConnect に関わる部分だけ。

## 手順

### 1. 判定: 新規か、利用中か

入力プロンプトを走査し、次のいずれかがあれば「利用中」、無ければ「新規」:

- 「SynapseConnect」「シナプスコネクト」の語
- 棚・group・記憶の棚など、SynapseConnect の概念への言及
- ツール名（add_memory / search_memory_facts / list_groups / get_fact_source など）
- スキル「記憶の検索」「記憶の記録」への参照

判定結果と根拠（該当した記述。新規なら「言及なし」）を、出力の最初に必ず書く。
判定に迷う場合（例: 別の記憶ツールの記述がある）は、迷った理由を書いたうえで「新規」として扱い、
既存の記憶ツールの記述との関係を「要判断」に回す。

### 2a. 新規 → 組み込み

1. `references/base-rules.md` を読み、版を選ぶ（チャットの指示欄向け=かんたん版 ／
   CLAUDE.md・エージェント向け=完全版。入力の文体と置き場所から判断し、選んだ理由を変更点一覧に書く）
2. 基本ルールを**ひとつの節としてそのまま**追加する。置き場所は、既存のツール・ルール節の隣か末尾。
   要素を選り好みして一部だけ入れない — 発動条件と不変ルールはセットで機能する
3. Obsidian 等のローカルノートの記述が入力にあれば、発動条件の「手元ノートを開く前」の行が
   効くことを変更点一覧で指摘する

### 2b. 利用中 → 監査と更新

1. `references/audit-checklist.md` の各項目と入力を突き合わせる
2. **差分だけを直す。**現行方針に合っている記述は文言ごと保持する（勝手に言い換えない —
   顧客が自分の言葉で書いた準拠記述は、そのままが検収しやすい）
3. 廃止方針（書き込みの事前承認・記録の削除や整理の指示・話題での棚分け・受け身の検索）は
   現行形へ置換し、変更点一覧に**新旧を並べて**書く
4. プロンプト内に検索・記録の詳細手順が書き込まれていたら、スキル参照の1行に置き換え、
   元の手順記述は変更点一覧へ移す（捨てない — スキル側と食い違う場合の照合材料になる）

### 3. 衝突チェック（新規・利用中とも）

既存の指示に次のような記述があれば衝突の候補:

- 「外部ツール・社外サービスを使わない/社内情報を送らない」（SynapseConnect は社外サービスに見える）
- 「自分の知識だけで答える」「情報源は◯◯のみ」（自動検索と矛盾）
- 「不要な情報は削除・整理する」（追記のみ原則と矛盾）
- 「確認なしに書き込まない」（こまめな自動記録と矛盾）

衝突は**黙って解決しない**。「要判断」として列挙し、それぞれに両立案を1つ添える
（例: 「外部ツール禁止」→「SynapseConnect は会社が契約した記憶基盤であり例外とする、の1行を追加する案」）。
どちらを採るかは読み手（顧客・管理者）が決める。

### 4. 記法を整える

修正後プロンプト全体ではなく、**自分が足した・変えた部分**に適用する:

- 1行1概念。理由や補足の従属節を書かない（理由は利用ガイドが持つ）
- 命令形。「〜してください」「〜するようになります」を使わない
- 参照されない番号付けをしない（箇条書きでよい）
- 棚の実名・ID・件数上限などの固有値を本文に残さない。見つけたら「設定メモ」への
  分離を提案し、本文は「設定メモに定めた◯◯棚」の参照に置き換える（チェックリスト項目12。
  棚の構成は変わるため、固有値が本文に散らばると変更のたびに全文書き換えになる）

## 出力の形（必ずこの3部、この順）

```
## 判定
新規 / 利用中 — 根拠: …

## 修正後プロンプト（全文）
（コードブロックで全文。省略しない）

## 変更点一覧
### 追加
- …（何を・どこに・なぜ）
### 変更（利用中の場合。新旧を並べる）
- 旧: … → 新: …（理由）
### 要判断（衝突。無ければ「なし」と書く）
- 衝突: … ／ 両立案: …
### 前提
- スキル「記憶の検索」「記憶の記録」の導入が前提（未導入なら利用ガイド3冊目から配置する）
```

## してはいけないこと

- 元プロンプトの役割・人格・SynapseConnect と無関係な業務ルールを変える／削る
- 衝突を黙って上書きして解決する
- 基本ルールの要素を一部だけ入れる（セットで1つの挙動）
- 修正後全文の出力を「変更箇所のみ」に省略する（貼り替えできる完成品を返す）

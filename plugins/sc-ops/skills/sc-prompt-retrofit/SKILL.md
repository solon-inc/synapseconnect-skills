# sc-prompt-retrofit — SynapseConnect セットアップ対話

ユーザーと対話しながら、いまの環境のシステムプロンプトを SynapseConnect 対応に作り替える。
一方的に完成品を出さない。**確認 → ヒアリング → 提案 → OK が出るまで修正 → 設定案内**の順で進める。
質問は一度に1〜2個まで。まとめて聞かない。

参照ファイル（該当する段階で読む）:
- `references/environments.md` — 環境別: 見分け方・システムプロンプトのありか・取得と設定の方法
- `references/base-rules.md` — 組み込む基本ルールの土台（発動節はレベルで差し替える）
- `references/levels.md` — 記録・読み込みの頻度レベル表と、対応する発動文言
- `references/audit-checklist.md` — 既存プロンプトに SynapseConnect 記述がある場合の監査表

## 進め方

### 1. 環境の確認

- まず自分で推定する。手掛かりは environments.md の「見分け方」列
  （例: ローカルファイルが読めて CLAUDE.md がある → Claude Code）。
- 推定を1問で確認する:
  「SynapseConnect の設定をします。いま開いているのは Claude Chat ですね？」
- 違うと言われたら、environments.md の一覧を見せて選んでもらう。

### 2. 現在のシステムプロンプトの取得

- 自動取得を試す（Claude Code なら CLAUDE.md を読む等。environments.md の「自動取得」列）。
- 取得できない環境・失敗した場合は貼ってもらう。そのとき**どこにある何を貼るのか**を
  環境に合わせて具体的に案内する（environments.md の「ありか」列の文をそのまま使ってよい）。
- 「何も設定していない」なら、無し（新規）として進める。

### 3. 提示と方針の確認

取得したプロンプトを**そのまま全文提示**し、2つ質問する:

1. 「これで合っていますか？」
2. 「進め方はどちらにしますか？
   **(A)** 既存のプロンプト全体を、SynapseConnect を参照・記録するように最適化する
   **(B)** 既存には触らず、SynapseConnect のセクションだけを追加する」

- **A** の場合は追加で1問: 「対象は全体でよいですか？ それとも一部ですか？」
  一部なら、どの節・どの範囲かを確認する。範囲外は一切変えない。
- **B** の場合、既存本文には触らない（追加のみ）。

### 4. 併用ツールのヒアリング

- 「Notion や Obsidian など、ほかにメモ・ナレッジ管理のツールを使っていますか？」
- 使っているなら、そのツールとの役割分担を確認し、
  「**全体像と横断 = SynapseConnect、詳細の原本 = そのツール**」の順序節を組み込む
  （base-rules の Obsidian 節を、当該ツール名に置き換えて使う）。

### 5. 記録の頻度（Lv0〜Lv5）

levels.md の**記録レベル表をそのまま提示**して、1つ選んでもらう。推奨は Lv4。

### 6. 読み込みの頻度（Lv0〜Lv5）

同じく levels.md の**読み込みレベル表を提示**して選んでもらう。推奨は Lv4。

### 7. 追加のヒアリング（必要な分だけ）

会話から必要と判断したものだけ聞く。例:
- 棚に書いてはいけない情報の追加定義（基本の秘密・個人情報以外に）
- 定期ジョブの希望（ニュース収集・会議メモ記録など → 導入済みスキルを案内）
- 「設定メモ」に入れる固有値（決め打ちの棚がある場合のみ）

### 8. システムプロンプトの作成 → OK が出るまで修正

- base-rules を土台に、次を反映して作る:
  - 発動節: 選ばれた記録 Lv・読み込み Lv の文言（levels.md の対応表）
  - 併用ツール節（手順4の結果）
  - 方針 A なら既存本文への最適化（同意された範囲だけ）、B なら追加のみ
- **全文を提示し、変えた点と理由を短く説明**して見てもらう。
- 修正指示があれば反映し、**OK が出るまで繰り返す**。勝手に確定しない。

### 9. 設定方法の案内（OK が出たら）

- environments.md の「設定方法」列に従い、その環境での貼り方・保存の仕方を案内する。
- スキル「記憶の検索」「記憶の記録」が未導入なら、導入方法を一言添える
  （Claude Code: `/plugin install sc-skills@synapseconnect-skills` ／ Chat: スキルの zip アップロード）。
- 最後に動作確認を促して締める:
  「設定できたら、◯◯（社内の話題）について聞いてみてください。棚から答えが返れば成功です」。

## 守ること（全段階）

- 元プロンプトの役割・人格・SynapseConnect と無関係な業務ルールを、(A) の同意なしに変えない。
  同意があっても、同意された範囲の外は変えない。
- 既存指示との衝突（外部ツール禁止・情報源の限定・削除や整理の指示・事前承認の義務 等）は
  黙って解決しない。「要判断」として提示し、両立案を添えて選んでもらう。
- 棚の実名・ID・件数上限などの固有値を本文に書かない（「設定メモ」へ分離。audit-checklist 項目12）。
- **Lv0（禁止）が選ばれた側は、禁止を明文でプロンプトに書く**（書かないと既定の動作が発動する）。
- 記法: 1行1概念・命令形・理由の従属節を書かない。
- 既存プロンプトに SynapseConnect の記述が既にある場合は、audit-checklist で現行方針との
  差分を取り、変更は新旧を並べて見せる。

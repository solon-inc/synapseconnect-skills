# チームの今週

チームの新着と型付き記録を、本人に聞かず次の行動を決められる1画面にする。

実行前に利用者の「設定メモ」を読む。

## 入力

- 期間。省略時は現在から直近7日。`今週` は設定タイムゾーンの月曜 00:00 から現在まで、`先週` は直前の月曜 00:00 以上・今週の月曜 00:00 未満とする。日付範囲も受け、始点を含み終点を含まない。
- 設定メモのタイムゾーン。無ければ利用者の現在地を推測せず確認する。

## 手順

1. 設定メモから、対象チームのメンバーとして明示された表示名・個人棚 ID、全社共有、開発チーム棚を読む。実行者・閲覧者はアクセス主体であり、設定メモで対象メンバーにも明示されている場合だけ集計へ含める。`classification=personal` や記録の `author_subject` だけで、実行者または別の人を対象メンバーへ足さない。
2. `list_groups` で、設定した各 ID が見えて個人棚は `classification=personal` であることを照合する。所有者名が公開されない環境でも、表示名や短縮 ID から所有者を推測しない。設定した完全な ID だけを使い、ID が無い、または分類が違う場合はその人を読まず「設定要確認」とする。必要なら、設定と取得済み `list_groups` 行を `scripts/plan_read_scope.py` に渡して、現行権限で読める範囲を決定的に分ける。利用者が求めた人数より設定メンバーが少ない場合、差分は「設定メモで未設定」とし、人や棚が存在しないとは断定しない。
3. 棚ごとに `get_updates(start='beginning', advance=false, limit=50)` を呼ぶ。個人棚は `origins=['obsidian']` と `origins=['mcp']` を分ける。`truncated=false` になるまで、返された `next_cursor` を明示して読む。必要なら `scripts/filter_period.py` で `created_at` を期間内に絞る。栞は進めない。全ページを読めない場合はその棚の期間集計を作らず、「期間を網羅できず集計不能」と coverage に出す。
4. 個人棚は `origin=obsidian` のノート名・変更種別を、そのメンバーの「やったこと」に最大3件出す。ノート名だけから進行中・詰まり・判断要を推測しない。要点化は求められたときだけ行う。意思決定・顧客更新を見る場合は必要な行だけ `get_episode` で本文を取る。
5. 全社共有と開発チーム棚では、`name` が `依頼:` `進捗:` `配信:` で始まる候補だけ本文を取り、本文の `依頼ID`／`配信ID` と `対象依頼`／`対象配信` で対を組む。進捗本文の `担当` が設定メモの表示名と完全一致するときだけ、そのメンバーの「進行中」または「詰まり・判断要」へ入れる。対応する記録が無ければ `なし` とする。
6. 個人棚ごとに `search_memory_facts` を1回だけ使い、原本の最終同期時刻・経過秒数と API の `stale` を確認する。`stale=true` の場合だけ「同期が止まっている可能性」と表示する。`stale=false` は設定された鮮度方針内、`stale=null` は経過時間を表示して「鮮度方針未設定のため判定不能」とする。経過時間だけから停滞警告へ変換しない。明示設定された `86400` 秒（24時間）の方針は維持するが、未設定時の既定値にはしない。

`plan_read_scope.py` への入力では、設定メモの全社共有・開発チーム棚の完全な ID をそれぞれ `company_group_id`・`development_group_id` に入れ、今回読む共有棚 ID の配列を `shared_groups` に入れる。必須の2設定が未設定、または片方が配列から欠落した場合、読める棚は引き続き返すが全体の準備完了とはしない。未設定の ID を名前や可視棚から補わない。

検索語から追加候補を探す必要がある場合だけ `search_episodes` を使う。候補行の `content_truncated=true` または `content_representation=bounded_prefix` は先頭 preview であり、必要な行は返された `full_content_lookup` の引数をそのまま `get_episode` へ渡して全文を読む。previewから不存在・唯一性・期限・依存関係を確定しない。`coverage.truncated` / `limit_reached` と行の `content_truncated` は別に扱う。必要なら取得済み応答を `../../scripts/plan_episode_evidence.py` で点検する。

## 根拠の境界

- `list_groups` は実行者から見える棚、`author_subject` は取得した記録の主体だけを示す。どちらも、見えない人・棚・記録が組織に存在しないことの証拠にはしない。
- 設定に無い対象は「未設定」、設定済みだが読めない対象は「現行権限では未確認」、読める範囲を検索して該当しない対象は「確認した可視範囲では見つからない」と区別する。
- 提出物のリンクや保管場所は、記録本文・添付・資料台帳などに明示された値だけを答える。確認した可視範囲に無いことから、担当者の手元、端末内、Obsidian vault の内外などの所在を推測しない。所在の根拠が無ければ「リンク・保管場所は未確認」とし、確認すべき相手または記録だけを示す。
- 記録された期限より早い中間期限を、残日数や作業順から事実として作らない。早めの対応を提案する場合は「提案」と明記し、記録上の期限と分ける。
- `状態`、`やったこと`、`次の一手`、`詰まり・判断要` を別々の明示情報として扱う。記録に因果や唯一性が無ければ、「判断が終わるまで初稿を出せない」「唯一の律速」のような依存関係へ広げず、残る行動を並列に示す。
- `reference_time`、`created_at`、`recorded_at` は各フィールドの値だけを報告する。最終保存値から、訂正前候補、訂正幅、無介入で正しく生成されたことを推定しない。生成・訂正の証跡が不足する点は「未確認」とする。
- 検索候補の `content` が先頭 preview の場合、その末尾や欠落部分を推測しない。候補集合が上限に達した場合も、対象が不存在・唯一とは断定しない。確定に使う本文は `get_episode` の全文と coverage を根拠にする。

## 出力

```text
# チームの今週（期間）
## <メンバー> — 最終同期と stale
- やったこと（3件まで）
- 進行中
- 詰まり・判断要

## 依頼と進捗の対
## 配信と進捗の対
## 読めなかった棚・止まっている棚
```

- 本文引用は各項目1文まで。詳細は記録 ID、または取得応答が実際に返した HTTPS `console_source_url` / `source_url` にする。URLを組み立てず、署名付き・認証付きURLを恒久参照として保存しない。記録そのもののConsole直リンクが返らない場合は「直接リンクは未提供」と明示し、記録IDからConsoleで探し直す必要があることを隠さない。
- 評価語、人別の件数比較、割合、ランキングを出さない。
- `group_unavailable` は「権限なし」、`ledger_unavailable` は「増えたか不明」、全ページを取り切れない場合は「期間を網羅できず集計不能」と区別する。
- 読めた棚だけで結果を返し、読めない棚のエラー本文を漏らさない。
- 要求人数、設定メンバー数、読めたメンバー数が異なる場合はそれぞれを分けて示す。設定にも可視範囲にも無い残り人数を、実行者や記録中の登場人物で埋めない。

個人棚の read 共有がまだ無い環境では、全社共有・開発チーム棚だけで依頼・進捗・配信をまとめる。これは個人棚3名分を読めたことや、read 共有機能の完成を意味しない。

## 受入を分ける

- SYN-183 前に確認できる範囲: 実行者本人の個人棚、全社共有、開発チーム棚が `list_groups` に現れること。本人の Obsidian 差分と共有棚の依頼・進捗・配信を指定期間でまとめる。この範囲が通っても「3名の今週」は完成扱いにしない。
- SYN-183 後にだけ確認する範囲: 他の各メンバーの個人棚が、設定した完全な ID と `classification=personal` のまま実行者の `list_groups` に現れて読めること。所有者名や短縮 ID から対応を推測しない。未付与の個人棚が見えないこと、他人の個人棚への書き込みが拒否されることも別に確認する。

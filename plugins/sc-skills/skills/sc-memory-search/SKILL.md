# 記憶の検索 — SynapseConnect で文脈を取る手順

発動は基本ルール（システムプロンプト）の「いつ動くか」に従う。

## 手順

1. 手がかりを決める: 話題から固有名詞（人名・会社名・案件名・商品名）を
   抜き出す。固有名詞が1つも無いときは、survey_space で全体像を眺めて
   当たりを付けるか、ユーザーに「どの案件の話ですか」と1つだけ確認する。
2. 広く → 狭く:
   a. 会話の冒頭・話題の転換時は survey_space で関係する棚の全体像をつかむ
   b. search_memory_facts で手がかりごとに検索する
      （1つの手がかりにつき1〜2回まで）
   c. 原文が必要なときだけ search_episodes で記録本文を引く
3. 出どころを確かめる: 答えに使う事実は get_fact_source で元の記録をたどる。
   原本（PDF 等）がある場合は get_source_url のリンクを添える。
4. 結果の読み方:
   - coverage（どこまで調べられたかの自己申告）を必ず読む
   - 「no_match（探したが無かった）」と「group_unavailable（棚に触れなかった）」
     を区別して伝える。0件を「存在しない」と断定しない
   - group_unavailable はリトライしない。そのまま報告する
5. 答え方: 棚から来た情報には出どころを添える。棚由来の情報と
   自分の一般知識を混ぜず、区別して示す。

## Obsidian を併用する場合

- 順序を守る: まず上の手順1〜2で SynapseConnect の全体像を取り、見つかった
  記録の source_ref やノート名を手がかりに、必要な箇所だけ Obsidian の
  該当ノートを開いて詳細を読む。
- いきなり Obsidian の全文検索から入らない（チームの文脈が抜けるため）。
- 答えでは出どころを分けて示す:
  「全体像 = SynapseConnect の記録◯◯ ／ 詳細 = Obsidian のノート◯◯」
- Obsidian で得た要点でチームにも役立つものは、「記憶の記録」スキルで
  棚へ戻す（元ノート名を source_ref に付ける）。

## 落とし穴

- 検索は話題ごとに数回まで。見つからないまま掘り続けない（無いことも情報）。
- 固有名詞なしの抽象語だけで検索しない（当たらない）。

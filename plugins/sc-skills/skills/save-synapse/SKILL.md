# 記憶の記録（/save-synapse）— SynapseConnect へ書き込む手順

発動は2通り。どちらも以下の同じ手順で記録する。

- **明示**: `/save-synapse` で呼ばれた、またはユーザーが「記録して」と言った
- **自動**: 基本ルール（システムプロンプト）の「発動」条件に当たった

## 明示的に呼ばれたとき（/save-synapse）

- 内容の指定があれば（`/save-synapse この決定を…` など）、その内容を記録の単位に切り出して手順1へ。
- 内容の指定が無ければ、**直近の会話から記録に値するもの**（決定・確定した事実・知見）を
  切り出し、下書き一覧（グループ・name・body）を提示してから記録する。
  該当が無ければ「記録に値する新しい内容が見当たりません」と正直に言う。
- 明示的な呼び出しでは、選ばれている記録レベル（Lv0〜Lv5）に関わらず記録してよい
  （Lv0 の環境だけは例外 — 禁止されている旨を伝えて記録しない）。

## 手順

1. 記録の単位を切り出す（粒度）:
   - 1件 = 1つの決定・事実・知見。「あとで1件だけ引いても意味が通る」
     大きさにする
   - 会議メモのような長文は、決定・宿題ごとに分割する
   - 悪い例: 議事録全文を1件（部分が検索で引けない）／
     1文ずつ10件（文脈が散る）
2. グループ（グループ）を選ぶ:
   a. list_groups でグループの一覧を確かめる
   b. **指定がなければ、必ずユーザーのプライベートグループ（個人グループ）に書く**
   c. 「組織で共有して」という指示・確認済みの合意があるときは、
      **組織のグループにも追加で書く**（個人グループに書いたうえで共有版を追加する。移動ではない）
   d. 他のグループも見て、内容と**明らかに関係するグループがあればそこにも書く**
      （迷う程度の関係なら書かない。話題やフォルダの名前だけで判断しない）
   e. 書き込みが権限エラーになったらリトライしない。書けたグループと書けなかったグループを報告する
3. 中身を書く:
   - name: 内容が一意に分かる見出し。固有名詞と日付を入れる
     （例: 「◯◯商事向け見積の値引き上限を10%に決定 — 2026-08-26」）
   - body: 3〜6文。固有名詞（人名・案件名・商品名）を主語に、
     いつ・誰が・何を・なぜ。数値・日付は丸めずそのまま書く
   - 分からない点は推測で埋めず「未確認」と書く
4. source_ref（出典）を必ず付ける:
   - 文書やページが元なら URL・文書名
   - 会議が元なら「会議◯◯ <日付>」
   - 会話から生まれた記録なら「会話 <日付>」
5. 投入して報告する:
   - add_memory で投入し、返ってきた記録 ID（episode_uuid）を控える
   - そのつど「記録しました: <name>（グループ名。複数のグループに書いたら列挙）」と1行で知らせる

## 書いてはいけないもの

- 認証情報・口座・個人の連絡先などの秘密（迷ったら書かずにユーザーに確認）
- 他人の個人情報、個人を評価する記述
- 外部ページ・手元ノートの本文の丸写し（要点に絞る。原本は元の場所に）

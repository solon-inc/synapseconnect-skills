# 記憶の検索（/load-synapse）— SynapseConnect で文脈を取る手順

発動は2通り。どちらも以下の同じ手順で検索する。

- **明示**: `/load-synapse` で呼ばれた、またはユーザーが「棚を調べて」と言った
- **自動**: 基本ルール（システムプロンプト）の「発動」条件に当たった

## 明示的に呼ばれたとき（/load-synapse）

- 調べたいことの指定があれば（`/load-synapse ◯◯案件の経緯` など）、それを手がかりに手順を実行する。
- 指定が無ければ、いまの会話の話題を手がかりに全体像を読み込み、要点を短く報告する。
- 明示的な呼び出しは、選ばれている読み込みレベルに関わらず実行してよい
  （Lv0 の環境だけは例外 — 禁止されている旨を伝えて検索しない）。

## なぜ SynapseConnect から始めるか

ほかのコンテキスト管理（Notion・Obsidian・Wiki・共有フォルダ）は「決まった場所にある情報を引く」道具。
SynapseConnect は「情報どうしの関係と全体感をつかむ」道具。先に棚で全体像をつかむと、
開くべき詳細ソースが絞れて無駄がない。逆順（いきなり個別ソースの検索）は、
チーム全体の文脈が抜けたまま個別情報の中で迷う。

## 手順

1. 手がかりを決める: 話題から固有名詞（人名・会社名・案件名・商品名）を
   抜き出す。固有名詞が1つも無いときは、survey_space で全体像を眺めて
   当たりを付けるか、ユーザーに「どの案件の話ですか」と1つだけ確認する。
2. 広く → 狭く:
   a. 会話の冒頭・話題の転換時は survey_space で関係する棚の全体像をつかむ
   b. search_memory_facts で手がかりごとに検索する
      （1つの手がかりにつき1〜2回まで）
   c. 原文が必要なときだけ search_episodes で記録本文を引く
3. 出どころを確かめる: 答えに使う事実は get_fact_source で元の記録をたどる。
   原本（PDF 等）がある場合は get_source_url のリンクを添える。
4. 結果の読み方:
   - coverage（どこまで調べられたかの自己申告）を必ず読む
   - 「no_match（探したが無かった）」と「group_unavailable（棚に触れなかった）」
     を区別して伝える。0件を「存在しない」と断定しない
   - group_unavailable はリトライしない。そのまま報告する
   - **鮮度を気にする**: 事実には時間の情報が付いている。新しい記録を優先し、
     古い記録と食い違ったら新しいほうを採る（判断に関わる食い違いは両方提示して確認）
5. 答え方: 棚から来た情報には出どころを添える。棚由来の情報と
   自分の一般知識を混ぜず、区別して示す。

## 他のコンテキスト管理ツール・Web と併用する場合

- 順序を守る: まず上の手順1〜2で SynapseConnect の全体像を取り、見つかった
  記録の source_ref・文書名・ノート名を手がかりに、必要な箇所だけ
  該当ツール（Obsidian・Notion・Wiki 等）や Web を開いて詳細を読む。
- いきなり個別ツールの全文検索や Web 検索から入らない。
- 答えでは出どころを分けて示す:
  「全体像 = SynapseConnect の記録◯◯ ／ 詳細 = ◯◯（ツール名・ノート名・URL）」
- 詳細調査で得た要点でチームにも役立つものは、「記憶の記録」スキルで
  棚へ戻す（元のノート名・URL を source_ref に付ける）。

## 落とし穴

- 検索は話題ごとに数回まで。見つからないまま掘り続けない（無いことも情報）。
- 固有名詞なしの抽象語だけで検索しない（当たらない）。

# 配信記録・設定・投稿の契約

07c管理の型付き記録共通契約から、配信に必要な固定部分を含めた単体配布用の契約。
共通契約を推測で変更せず、差分が生じたら両fixtureを照合してから更新する。

## 必要な値とその決め方

各値は 設定メモ > `.synapse/shelves.json` > `list_groups` の自動解決 > 既定 の優先順位で決める。
実値は利用者側の設定メモ（任意、`docs/config-template.md` の雛形）か `.synapse/shelves.json` にだけ置き、
この契約や SKILL.md には書かない。

| 値 | 設定メモ | 保存ファイル／自動解決 | 既定 |
|---|---|---|---|
| SynapseConnect Console のトップ URL | 上書き可 | — | `https://console.synapse-connect.ai/console` |
| `share.dry_run` | 上書き可 | — | `true` |
| Chatwork 投稿ツール名 | 上書き可 | 利用可能なツール名に `chatwork` を含み、送信系（send / post / message）のものを自己検出。複数なら1回確認、0件なら投稿しない | なし（プレビューのみ） |
| 全社共有・開発チーム棚の完全な ID（テスト入力では `company_group_id`・`development_group_id`） | 上書き可 | `resolve_shelves.py` の `roles.company` / `roles.development` | なし（`ask_user`） |
| 宛先表（allowlist） | 宛先・棚・room ID・To account ID（個人向けだけ必須）・通知先（`個人向け`／`全社向け`／`チーム向け`）。**人が書いた設定メモだけ** | なし（スキルは宛先をどこにも保存しない。`.synapse/shelves.json` は棚の役割だけ） | なし（投稿しない） |

宛先の名前→ID は、Chatwork MCP の room / contact 一覧・検索ツールで引いてよいが、
表示名が完全一致する1件のときだけ採用し、部分一致・別名・推測値では採用しない。
宛先表が無い、または宛先が表に無い場合は、ユーザーが確認すれば配信記録は作るが
**投稿はせず**、プレビューと手動投稿用本文（`[To:]` 無し）だけを返す。名前引きで得た ID を
宛先表に書き足さない。会話で渡された room ID は使わない。
room ID と To account ID は記録本文や通常の実行報告へ出さない。

記録・投稿前に、通知先が `個人向け`・`全社向け` なら全社共有 ID、
`チーム向け` なら開発チーム棚 ID と、宛先行の `group_id` が完全一致することを確認する。
通知先が不明、対応する棚が未設定（`ask_user`・`absent`）、または ID が不一致なら、プレビューの
確定済みでも記録・投稿をせず「設定要確認」で停止する。名前・別名・部分一致で代用せず、宛先行や
送信先を自動訂正しない。

## 配信記録

`name` は `配信: <30字以内の要点> — <yyyy-mm-dd>`。nameのコロンは半角、末尾は
記録日とする。配信IDと`ingest_key`は同じ
`share-<yyyymmdd>-<hhmm>-<小文字ASCII・数字・ハイフンのslug>` とする。
同じプレビュー、確認、結果照合では同じIDを使う。

`add_memory` の引数:

| 引数 | 値 |
|---|---|
| `name` | 上記の固定書式 |
| `group_id` | 個人・全社向けは全社共有、チーム向けは開発チーム棚 |
| `ingest_key` | 配信ID |
| `source_ref` | 入力または取得した不透明な参照。分解・再構成しない |
| `reference_time` | 配信時刻のISO 8601、タイムゾーン付き |

本文の見出しは行頭固定・全角コロン（`：`）・コロン直後の空白なしで書く。

```text
種別：配信
配信ID：share-20260917-1030-example
配信者：<表示名>
宛先：<表示名／チーム／全員>
通知先：個人向け／全社向け／チーム向け
要点：<受け手が次の行動を取れる1〜3文>
一言：<任意。無ければ なし>
元記録：<不透明な参照>
添付：なし または 原本への不透明な参照
日時：<ISO 8601、タイムゾーン付き>
```

同じ`ingest_key`の再送が`replayed: true`なら既存記録を採用する。`record_mismatch`、
timeout、結果不明ではChatworkへ進まず、同じキーの結果を照会できる場合だけ照会する。

## Chatwork 投稿文

```text
[To:<account_id>]
[info][title]【共有】<要点タイトル>[/title]<一言。無ければ省略>
・<要点1>
・<要点2>
詳細: <Console トップ URL>（記録ID: <episode_uuid>）
配信ID: share-20260917-1030-kintone-spec（着手したら「進捗を残す」で「対象配信：」にこのIDを）[/info]
```

- `[To:]` は個人向けだけに付ける。全社向け・チーム向けには付けない。
- 初回プレビューでは `<episode_uuid>` を `<記録後に確定>`、To account ID を
  `<設定済み>` と表示する。承認後、`add_memory` が成功したときに記録 ID だけを
  返された値へ差し替える。
- 要点が1文または3文なら箇条書き数も合わせる。
- Console に記録詳細の安定URLが返る場合は、その URL を `詳細:` にそのまま使う。
  返らない場合はトップ URL（設定メモに無ければ既定 `https://console.synapse-connect.ai/console`）と
  記録 ID を併記し、URL形式を推測しない。
- 署名 URL、入力本文、schema、秘密、個人の連絡先は投稿しない。
- 添付 URL がある場合も形を解釈・書き換えず、配信記録の `添付:` に置く。
  Chatwork では `詳細:` の配信記録から辿らせ、ファイルを直接添付しない。

## 結果別の停止条件

| 結果 | 次の動作 |
|---|---|
| プレビューのみ | 外部ツールを呼ばず、確認を待つ |
| 宛先表が無い・宛先が表に無い | 確認後に記録は作るが投稿せず、記録 ID と手動投稿用本文を返す。room ID・To account ID は表示しない |
| Chatwork ツールが0件 | 投稿せずプレビューと手動投稿用本文を返す |
| `add_memory` 成功 | 返った記録 ID を投稿文へ入れ、Chatwork を1回呼ぶ |
| `add_memory` 失敗・不明 | Chatwork を呼ばず停止。再実行前に同じ `ingest_key` を照合 |
| Chatwork 成功 | 配信 ID、棚、記録 ID、投稿先の表示名を報告 |
| Chatwork 失敗・不明 | 自動再送せず、記録 ID、投稿先の表示名、手動投稿用本文を返す。個人向け本文から `[To:]` を外し、room ID・To account ID は表示しない |

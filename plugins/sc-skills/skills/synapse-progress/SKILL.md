# 進捗を残す

依頼または配信への進捗を、対象 ID と対応付けた記録として1件残す。

棚とタイムゾーンは下の「棚の決め方」で実行時に決める。グループの実名・ID はこのスキルに書かない。

## 棚の決め方

棚・タイムゾーン・上限は、キーごとに 設定メモ > `.synapse/shelves.json` > `list_groups` の自動解決 > 既定 の優先順位で決める。

1. プロジェクトのナレッジ／CLAUDE.md に `# SynapseConnect 設定メモ` 見出しのブロックがあれば、
   そこに書かれた項目（全社共有・開発チーム棚・タイムゾーン）を最優先で使う（0.8 以降、設定メモは任意で上書き用）。
2. 設定メモに無い項目は `list_groups` を1回呼び、その JSON をそのまま
   `../../scripts/resolve_shelves.py` に渡して解決する（設定メモがあれば `--memo-overrides` に
   JSON で渡す）。このスキルが使うのは `roles.company`、`roles.development`（対象記録を探す棚）と
   `defaults.timezone`（既定は OS のタイムゾーン）。進捗の書き込み先そのものは対象記録の棚で決まる。
3. 使う役割が `ask_user` なら、候補（group_id と description）を提示して1回だけ選んでもらい、
   `--save-choice <役割>=<group_id>` で `.synapse/shelves.json` に保存する。
4. `personal_self` が `stop` なら書かずに理由を伝える。`roles.development` が `absent` なら
   対象記録は全社共有だけで探す。

## 固定形式

- `name`: `進捗: <対象の要点> — <着手／途中／完了／詰まり> — <yyyy-mm-dd>`
- `group_id`: 対象の依頼または配信と同じ棚
- `ingest_key`: `prog-<対象ID>-<連番2桁>`
- `source_ref`: 対象記録の不透明な参照。無ければ対象の依頼 ID または配信 ID
- `reference_time`: 送信直前に信頼できる現在時計から取得した時刻（ISO 8601、タイムゾーン付き）

本文は次の行頭と全角コロンを変えない。`対象依頼` と `対象配信` は一方だけを書く。

```text
種別：進捗
進捗ID：<ingest_keyと同じID>
対象依頼：<依頼ID。配信への進捗ではこの行を対象配信に置き換える>
担当：<表示名>
状態：着手／途中／完了／詰まり
やったこと：<1〜3文>
次の一手：<1文。完了なら なし>
詰まり・判断要：<1文または なし>
```

## 手順

1. 対象の依頼 ID または配信 ID、対象記録の棚、現在の状態を確認する。対象 ID が不明なら推測せず1つだけ確認する。対象記録は「棚の決め方」で決めた全社共有・開発チーム棚から探す。
2. 状態を `着手`、`途中`、`完了`、`詰まり` から選ぶ。やったこと、次の一手、詰まり・判断要を短く整理する。
3. 対象記録と同じ棚を使う。対象が依頼なら `対象依頼`、配信なら `対象配信` を本文に1行だけ書く。
4. `prog-<対象ID>-<連番2桁>` を進捗 ID と `ingest_key` に使い、固定形式の本文を作る。
5. 送信直前に `../../scripts/current_reference_time.py` を実行するか、利用環境の同等な現在時計を1回読む。`defaults.timezone`（設定メモにあればその値）を `--timezone` に渡し、無ければ省略して OS のタイムゾーンに任せる。その返り値を加工せず `reference_time` に使い、日付部分を `name` の末尾日付に使う。会話時刻、メッセージの表示時刻、モデルの推測で埋めない。時計を取得できない、または取得後に送信が中断した場合は送信せず、現在時計を取り直す。
6. API キー、token、password、cookie、口座、個人の連絡先、個人の評価表現が無いことを確認し、`add_memory` を1回だけ呼ぶ。
7. 進捗 ID、対象 ID、状態、棚、記録 ID、実際に渡した `reference_time` を報告する。

## 止まる条件

- 対象 ID または対象の棚を確認できない（棚が `ask_user` のまま、または `stop` を含む）。
- 依頼と配信の両方を1件の進捗で参照しようとしている。
- 対象と異なる棚しか書けない。
- API キー、token、password、cookie、口座、個人の連絡先、個人の評価表現が含まれる。
- 信頼できる現在時計を取得できない。
- timeout、結果不明、`record_mismatch`。新しい連番で埋め合わせない。

担当者ごとの件数比較や評価は行わない。

# 進捗を残す

依頼または配信への進捗を、対象 ID と対応付けた記録として1件残す。

実行前に利用者の「設定メモ」を読む。

## 固定形式

- `name`: `進捗: <対象の要点> — <着手／途中／完了／詰まり> — <yyyy-mm-dd>`
- `group_id`: 対象の依頼または配信と同じ棚
- `ingest_key`: `prog-<対象ID>-<連番2桁>`
- `source_ref`: 対象記録の不透明な参照。無ければ対象の依頼 ID または配信 ID
- `reference_time`: 進捗を残した時刻（ISO 8601、タイムゾーン付き）

本文は次の行頭と全角コロンを変えない。`対象依頼` と `対象配信` は一方だけを書く。

```text
種別：進捗
進捗ID：<ingest_keyと同じID>
対象依頼：<依頼ID。配信への進捗ではこの行を対象配信に置き換える>
担当：<表示名>
状態：着手／途中／完了／詰まり
やったこと：<1〜3文>
次の一手：<1文。完了なら なし>
詰まり・判断要：<1文または なし>
```

## 手順

1. 対象の依頼 ID または配信 ID、対象記録の棚、現在の状態を確認する。対象 ID が不明なら推測せず1つだけ確認する。
2. 状態を `着手`、`途中`、`完了`、`詰まり` から選ぶ。やったこと、次の一手、詰まり・判断要を短く整理する。
3. 対象記録と同じ棚を使う。対象が依頼なら `対象依頼`、配信なら `対象配信` を本文に1行だけ書く。
4. `prog-<対象ID>-<連番2桁>` を進捗 ID と `ingest_key` に使い、固定形式の `name` と本文を作る。
5. API キー、token、password、cookie、口座、個人の連絡先、個人の評価表現が無いことを確認し、`add_memory` を1回だけ呼ぶ。
6. 進捗 ID、対象 ID、状態、棚、記録 ID を報告する。

## 止まる条件

- 対象 ID または対象の棚を確認できない。
- 依頼と配信の両方を1件の進捗で参照しようとしている。
- 対象と異なる棚しか書けない。
- API キー、token、password、cookie、口座、個人の連絡先、個人の評価表現が含まれる。
- timeout、結果不明、`record_mismatch`。新しい連番で埋め合わせない。

担当者ごとの件数比較や評価は行わない。
